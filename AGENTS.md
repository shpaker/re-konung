# Правила для AI-агентов

re-konung — изучение и воссоздание движка игр серии «Князь» (1С/Snowball): сначала «Князь: Легенды Лесной страны» (1999), затем «Князь 2» и «Князь 2.5», если подтвердится общий движок (см. [docs/games.md](docs/games.md)). Работу ведут агенты, поэтому всё, что узнали о форматах, записывается в [docs/](docs/README.md), а не остаётся в чате.

## Стадия

Этап 1 — карты первой части в Tiled. Есть эталонный разбор на Python (`konung/`), расширение Tiled (`tiled/konung/`), которое открывает оригинальные `Konung.N` вместе с игровыми объектами из `Game.N` и сохраняет их обратно, и описания форматов в `docs/k1/formats/`. Записываются только карты (`Konung.N`) и начальное состояние новой игры (`Game.N`: персонажи, отряды, клады, переходы); спрайты, `GRAPH.RES` и `Objects.res` лишь читаются.

- Любое изменение записи карты или `Game.N` проверяется так: все файлы обоих изданий после «прочитать → записать» должны совпасть с оригиналом побайтно (тесты `tests/k1/test_maps.py` и `tests/k1/test_game_state.py` для Python; для расширения — сохранить из Tiled и сравнить).

- `konung/` — Python-пакет, CLI `konung` (`uv run konung --help`). Общее для частей — в корне пакета (`binary`, `rle`, `palette`, `disc`), своё у каждой части — в `konung/k1/`, позже `konung/k2/`.
- `tiled/konung/` — расширение Tiled: `lib/k1.mjs` — разбор без Tiled API, `konung.mjs` — сборка карты Tiled. Логика повторяет Python, и при расхождении прав Python: у него тесты.
- `crates/` — Rust-workspace: крейт `k1-data` — данные игры K1 (репозиторий `repo`, форматы `map` и `game_state`, правки состава `game_edit`, графика `graph_res`, `objects_res`, `lights_res`, `flames_res`, `rle` и таблицы из EXE), повторяет Python и пока ничего не заменяет; при расхождении прав Python. Трейты-абстракции объявляет потребитель, когда нужен мок. Подробности — [docs/rust.md](docs/rust.md).
- `tests/` — pytest. Тесты на данных берут файлы из `original/` и пропускаются, если их нет.
- `original/` — файлы своей копии игры (образы дисков и распакованное), в git не попадают. Как подготовить — [docs/k1/editions.md](docs/k1/editions.md).
- `out/` — всё, что сгенерировано (PNG, выгрузки), в git не попадает.

## Реверс

Цикл — навык `konung-reverse-format` (`.claude/skills/konung-reverse-format/SKILL.md`): гипотеза → проверка скриптом на реальных файлах → тест → запись в `docs/`.

- Каждое поле в описании формата помечено уверенностью: **подтверждено** (есть тест или проверка на всех файлах), **гипотеза**, **неизвестно**. Неизвестные байты не выкидываются: парсер сохраняет их в поле `unknown`.
- Источник факта указывается всегда: наш эксперимент или внешний источник из [docs/sources.md](docs/sources.md).
- [Marisa-Chan/Slavik](https://github.com/Marisa-Chan/Slavik) — реимплементация движка на C++, клон лежит в `../../Marisa-Chan/Slavik` (`E:\github\Marisa-Chan\Slavik`). Это справочник **только для чтения**: лицензии у него нет, поэтому код оттуда не копируется. Форматы описываются своими словами со ссылкой на файл и строку, реализация пишется своя.
- Издания различаются (RUS, ENG, позже GOG и коллекционное): прежде чем обобщать, проверить факт на всех изданиях из `original/`.

## Авторский контент

Игры серии — чужая собственность. Проект изучает форматы и пишет свой код, но игру не распространяет.

- Ни в git, ни в PR, issue, комментариях и релизах нет файлов игры и производных от них: спрайтов, рендеров карт и PNG, звука, музыки, текстов, роликов, дампов ресурсов. Всё это живёт в `original/` и `out/`, которые в git не попадают.
- Не писать, где скачать игру или образы дисков: никаких торрентов, сайтов-архивов старых игр, Internet Archive и файлообменников. Можно только два пути: свой диск или покупка в магазине.
- Фикстуры тестов только синтетические. Тесты на данных игры идут только локально, на `original/`.
- В `docs/` форматы описываются своими словами: смещения, размеры, имена файлов, короткие фрагменты заголовков. Кусков ресурсов там нет.
- Релизы собирают только наш код (`just tiled-package`).
- Хук prek `no-game-files` не пускает в коммит файлы игры, а `no-download-links` — ссылки на раздачи. Если хук сработал, исправить текст или файл; обходить хук нельзя.

## Агенты

С проектом работают Claude Code и другие агенты; правила для всех — этот файл. Подробности — [docs/agents.md](docs/agents.md).

- Навыки для разработки — `.claude/skills/`. Навыки для людей — `skills/`: репозиторий раздаёт их как плагин для Claude Code, Codex и Qwen Code ([docs/agents.md](docs/agents.md)).
- Карты в Tiled агент смотрит и правит через плагин [tiled-mcp](https://github.com/shpaker/tiled-mcp) (навык `tiled`). Оригинальные карты открываются в нём напрямую, через расширение `tiled/konung/` (`just tiled-install` или навык `konung-tiled-install`).
- Нашёл баг или недостающую функциональность в чужой утилите или библиотеке (Tiled, uv, Pillow, 7-Zip, Slavik и др.) — явно сообщить пользователю в чате: что не так, как воспроизвести, ссылка на репозиторий и место в коде, если оно известно. Исправление не предлагать и молча не обходить: что с этим делать, решает пользователь.
- То же в репозиториях `shpaker/*` (например, [tiled-mcp](https://github.com/shpaker/tiled-mcp)) — можно сразу сделать PR с исправлением в том репозитории, но в **отдельной сессии** и спросив пользователя. В текущей работе не обходить, а сообщить так же, как о чужом баге.
- Проверки — [prek](https://prek.j178.dev) (`prek.toml`): git запускает его на коммите и перед push. Шимы ставит `just setup`.

## Стиль кода

- Python 3.14, ruff. Комментарии и сообщения — на русском, имена — на английском, без сокращений.
- Парсер формата — чистая функция `parse(data: bytes)`, файловая система — отдельно (`load`).
- Тесты простые: синтетические — для алгоритмов (RLE), на реальных файлах — для форматов.

## Обязательно

- После правок: `just check` (ruff, тесты, проверки файлов).
- Проверки prek не обходить: никаких `--no-verify`, `SKIP=`, `prek uninstall`.
- Изменение формата видно на картинке — проверить картинкой: `uv run konung k1 map …` и рендер в Tiled.
- Решения и найденное о форматах записывать в `docs/`.

## Git

- Все изменения — только через PR. Один PR закрывает одну область: каркас, распаковку дисков, графику, карты, расширение Tiled, документацию по теме. Несвязанное — в разные ветки и PR.
- Любые записывающие git-операции (commit, push, merge, rebase, reset, tag и т. п.) — только с явного подтверждения пользователя.
- В `main` ничего не пушить и не мержить (в том числе `gh pr merge`) без явного согласия пользователя именно на этот push или merge.
- Коммиты — только от лица пользователя, в формате Conventional Commits на английском.
- Нигде — в коммитах и их метаданных, ветках, PR, issue, комментариях, тегах и релизах — никаких упоминаний ИИ и нейросетей (`Co-Authored-By`, `Generated with ...`, `claude/`, `ai/` и т. п.).
- Создавая PR, прочитать [CONTRIBUTING.md](CONTRIBUTING.md) и заполнить все его разделы.
- Версия считается автоматически (git-cliff), а теги и релизы ставятся только вручную, workflow **version** ([docs/releases.md](docs/releases.md)). Агент его не запускает и теги не ставит. Тип коммита и заголовка PR определяет следующую версию, поэтому выбирать его надо честно: `feat` — новая возможность, `fix` — исправление, остальное релиза не даёт.
