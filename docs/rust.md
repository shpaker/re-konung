# Rust-реализация

Cargo-workspace в `crates/` (edition 2024). Повторяет Python-пакет `konung/` слой за слоем; Python — эталон, и при расхождении прав Python (AGENTS.md). Пока Rust ничего не заменяет: Python-CLI и расширение Tiled остаются как есть.

## Крейты

| Крейт | Что внутри | Статус |
|---|---|---|
| `k1-data` | данные игры K1: репозиторий (`repo`), форматы карт и состояния (`map`, `game_state`), правки состава (`game_edit`) и графика (`rle`, `palette`, `graph_res`, `objects_res`, `lights_res`, `flames_res`, `executable`, `characters`) | `Konung.N`, `LIGHTS.N`, `Game.N`: разбор и побайтно точная запись; добавление/удаление персонажей сохраняют укладку; `GRAPH.RES`, `Objects.res`, `LIGHTS.RES`, `FLAMES.RES` и таблицы из EXE читаются; кадры персонажей собираются; тесты на `original/` |
| `k1-game` | специфика K1: ресурсы (`resources`), ключи текстур и RGBA-декодирование (`textures`), список отрисовки карты (`scene`) | сцена строится по эталону `konung/k1/render.py` (порядок, сортировка по нижнему краю, тени, огни, персонажи, оверлеи); headless, без Bevy; тесты на `original/` |
| `kn-game` | общий фасад: `Game` (открыть каталог, карты, сцена, текстуры, headless-`check`), Bevy-независимая модель `Scene`/`Piece`/`TextureId` | скрывает K1 за общим API; до появления K2 в нём только фасад и модель сцены — никаких «общих игровых правил»; `CheckReport` сериализуется в JSON |
| `kn-io` | Bevy: кэш текстур (`textures`), куски сцены → спрайты (`scene`), камера (`camera`) | Bevy 0.20, окно и GPU нужны только для запуска, не для тестов |
| `kn-viewer` | бинарь `re-konung-viewer`: окно с картой, Feathers-UI, headless-`check` | `check` работает без окна и GPU, возвращает ненулевой код при ошибке |
| `kn-exec` | бинарь `re-konung`: запуск игры | заготовка — стартовая карта новой игры тем же конвейером; игрового процесса нет |

Будущие крейты: `k2-data`, `k2-game`. Общее выделяется, только когда появится второй конкретный потребитель, — та же логика, что в [games.md](games.md) про проверку общности движка на K2.

## Слои `k1-data`

```
данные игры (original/k1/<издание>/game)
  → repo: GameDir — поиск файлов без учёта регистра, номера карт и состояний, чтение байтов; FileSet (игра/обучение)
    → map: чистые parse(&[u8]) / serialize — KonungMap, Lights; ФС не трогают
    → game_state: чистые parse(&[u8]) / serialize — GameState (предметы, отряды, клады, переходы, персонажи, деревни), on_map и геометрия мелкой сетки
    → game_edit: add_character / remove_character на GameState — правки держат плотную укладку отрядов и переписывают все ссылки; API принимает номера записей, а не объекты (в Rust нельзя занять запись и одновременно править состояние)
    → графика, только чтение: rle и palette (декодирование картинок, RGB555), graph_res (тайлы, спрайты персонажей), objects_res (объекты и монстры), lights_res (маски света), flames_res (огни), executable (таблицы снаряжения, порядка слотов и огней из EXE), characters (сборка кадра персонажа со снаряжением и тенью)
      → {игровые данные, Tiled} — слои выше появятся позже
```

Тестируемость: форматный слой тестируется подменой данных, а не реализаций; `GameDir` dyn-совместим (методы `&self`, конкретные типы возврата). Трейты для моков объявляет потребитель, когда они ему действительно понадобятся («accept traits, return structs»); провайдерских трейтов в `k1-data` нет.

## Слои сцены (`k1-game` → `kn-game`)

```
k1-data (форматы)
  → k1-game: resources — загрузка графики из GameDir; textures — ключи текстур и RGBA-декодирование; scene — список отрисовки карты (порядок render.py)
    → kn-game: Game — фасад (open/maps/heroes/scene/textures/check); Scene/Piece/TextureId — общая модель, K1-типы наружу не выходят
      → kn-io: textures — TextureCache (RGBA → Image, один ассет на ключ); scene — куски → спрайты; camera — панорама, ступенчатый масштаб, границы
        → kn-viewer (re-konung-viewer) и kn-exec (re-konung) — бинарники
```

Зависимости идут только вниз: `kn-io` и бинарники не знают о K1, `kn-game` не знает о Bevy, `k1-data` — ни о том ни о другом.

Порядок наложения сцены повторяет эталон `konung/k1/render.py`: земля → верхний слой → декорации (сырые пропускаются) → слой теней → объекты с огнями и персонажи, отсортированные по нижнему краю (ключ `(bottom, вид, слот)`, устойчивая сортировка — огни объекта остаются над его картинкой) → оверлеи: свет, проходимость, маркеры `Game.N`. Текстовые подписи маркеров не рисуются: в модели сцены нет текста, его показывает UI просмотрщика. Кольца маркеров — растеризованное приближение PIL-эллипса толщиной 3.

GRAPH.RES и OBJECTS.RES заимствуют буфер, поэтому `Resources` хранит их байтами и разбирает на время операции (`with_graphics`); владеющие таблицы EXE, маски света и огни разбираются один раз. Анимаций по времени пока нет — кадр статичен, как эталонный рендер.

`check` берёт начальное состояние по источнику карт: `Game.N` для игры, `TGame.N` для обучения. Одно состояние на оба источника расставляло бы по картам обучения персонажей основной игры (в ENG это давало 17 и 5 персонажей вместо 8 и 2). Ошибка одной карты попадает в её строку отчёта и не прерывает проверку остальных; недостающая текстура отличается от пустого слота и несёт причину (битое декодирование, палитра вне банка).

Бинарные данные не считаются заведомо целыми: `rle` отсекает размеры за пределом `MAX_DIMENSION` и пропуски за ширину строки, `graph_res` проверяет, что палитра тайла помещается в банк цветов, `objects_res` — что число огней не превышает 20 слотов. Иначе следующее за чтением вычитание или аллокация паниковали бы на битом файле. Проверка пропуска зеркалирована в Python-эталон и в расширение Tiled — все три реализации формата остаются одинаковыми.

## Отображение (`kn-io` и бинарники)

Bevy 0.20; окно и GPU нужны только чтобы запустить бинарь, тесты идут без них.

- **Координаты.** Пиксели карты — y вниз, угол слева вверху; спрайт Bevy позиционируется по центру и живёт в мире с y вверх. Поэтому кусок `(x, y, w, h)` получает центр `(x + w/2, −(y + h/2))` (`kn_io::piece_transform`). Отрицательные x и y у объектов и спрайтов не отбрасываются — как `render.blit`.
- **Порядок наложения** передаётся через z: прозрачные спрайты 2D сортируются по возрастанию z (`bevy_sprite_render`: `sort_key = FloatOrd(transform.z)`), поэтому n-й кусок сцены получает `z = n · Z_STEP`.
- **Кэш текстур.** `TextureCache` хранит по ассету на ключ `TextureId`; на карту ~6–13 тыс. кусков и ~250–300 уникальных текстур, так что спрайты делят `Handle<Image>`. Фильтрация — `ImagePlugin::default_nearest()`, графика пиксельная.
- **Иерархия.** Спрайты карты — потомки корня `MapRoot`, и корню обязательны `Transform` и `Visibility`: `propagate_parent_transforms` обходит деревья от корней с `Transform`, а `sync_simple_transforms` пропускает сущности с `ChildOf`. Без `Transform` у корня потомки не получают `GlobalTransform` и не попадают в рендер — окно пустое, хотя сущности на месте.
- **Камера.** Ступени масштаба дискретные (`ZOOM_LEVELS`, `scale = 1 / zoom`), чтобы на целых значениях картинка оставалась пиксель-в-пиксель; одна ступень — щелчок колеса или ~100 пикселей свайпа (`ZoomScroll` с порогом, иначе инерция трекпада пролистывает весь диапазон за жест). При смене карты `frame_scene` наводит камеру на центр содержимого и подбирает ступень, на которой оно влезает в окно (`fitting_zoom`): наведение отложено в `PendingFrame`, потому что камеру спавнят команды и в `Startup` её ещё нет. Границы камеры — прямоугольник содержимого, а не вся сетка 80×160: нарисована бывает только её часть. Панорамирование: WASD и стрелки, перетаскивание левой кнопкой — над интерфейсом отключено, иначе список карт двигал бы карту.
- **Интерфейс просмотрщика** — Bevy Feathers (фича `bevy_feathers`): состояние (`Viewer`) отделено от виджетов, обработчики правят только его и оставляют `Rebuild` с причиной (`Map` — навести камеру заново, `Overlays` — оставить кадр как есть), а сцену перестраивает одна система. `Checkbox` в Bevy считает новое значение как `!Has<Checked>` и сам `Checked` не пишет, поэтому обработчик синхронизирует его вручную (как `checkbox_self_update`) — иначе каждый клик шлёт `true`. Подписи на английском: у встроенного шрифта Feathers нет гарантии кириллицы. Персонажи включены по умолчанию (`DEFAULT_OVERLAYS`), и `Checked` у этого чекбокса должен этому соответствовать.

## Запуск

```bash
cargo run --release --manifest-path crates/Cargo.toml -p kn-viewer -- \
    --game-dir original/k1/rus/game [--map N] [--source tutorial]

cargo run --release --manifest-path crates/Cargo.toml -p kn-exec -- \
    --game-dir original/k1/rus/game
```

Headless-диагностика — без окна, GPU и рендерера; её же используют CI и агенты:

```bash
… -p kn-viewer -- --game-dir original/k1/rus/game check --map 1
… -p kn-viewer -- --game-dir original/k1/rus/game check --all [--format json]
```

Код возврата ненулевой, если карта не собралась или её текстура не декодировалась. Оригинальные файлы только читаются.

## Проверки

`crates/` проверяются и локально, и в CI (job `rust` в `.github/workflows/ci.yml`: fmt, clippy, тесты). С появлением Bevy job `rust` компилирует его дерево зависимостей — это минуты, кэш в CI не настроен. На Linux сборке Bevy нужны системные `-dev` пакеты (wayland, x11, ALSA, udev) — в CI их ставит отдельный шаг, список взят из `docs/linux_dependencies.md` в крейте `bevy`; на macOS они не нужны.

```bash
just cargo-test   # тесты: синтетические всегда, на данных — если есть original/
just cargo-lint   # cargo fmt --check + clippy -D warnings
```

Окно и GPU для тестов не нужны: `kn-game` и `k1-game` Bevy не используют, а `kn-io` и `kn-viewer` проверяют чистую логику — координаты и z-порядок кусков, ступени масштаба, разбор CLI, переключатели оверлеев, отчёт об ошибке. Сквозная проверка без окна — `check` (см. «Запуск»): на ENG все 43 карты игры и обе карты обучения собираются без ошибок, в release это секунды.

Запись (`serialize`, `serialize_lights`) проверяет точную геометрию сеток до записи, а не только итоговый размер: строки 81 и 79 клеток дают верное число байтов, но сместили бы границы строк. Та же проверка добавлена в Python-эталон (PR #18) — на валидных картах реализации идентичны побайтно.

Тесты на данных (`crates/k1-data/tests/original.rs`, `original_game_state.rs`, `original_game_edit.rs` и `original_graphics.rs`) повторяют `tests/k1/test_maps.py`, `test_game_state.py`, `test_game_edit.py` и `test_graphics.py`: parse → serialize побайтно для всех `Konung.N`, `Game.N`/`TGame.N` и `LIGHTS.N`/`TLIGHTS.N` обоих изданий, `Tutorial.4/5` (ENG) с единственной сырой декорацией в слоте 994; ссылки между блоками состояния, стартовая клетка героя и независимая сверка смещений полей персонажа (`0x2A69A`); плотная укладка до и после правок состава, рост резерва, копия NPC со своим отрядом и своими предметами, атомарность правки без места; GRAPH.RES разбирается до последнего байта, спрайты упираются в границы блоков, простые и динамические объекты на месте, таблицы EXE находятся однозначно, кадры огней совпадают с анимациями, каждый персонаж на каждой карте рисуется. Тесты на данных без `original/` пропускаются (пустой список изданий с сообщением в stderr), но если `original/k1` существует и ни одно издание не нашлось — тесты падают: иначе они «проходили бы», ничего не проверив. На CI `original/` нет, там корректный пропуск.

Графические форматы read-only: побайтного round-trip для них нет, поэтому порт сверялся с Python-эталоном кросс-языковыми дайджестами — RGBA-байты тайлов, кадров спрайтов и банка цветов GRAPH.RES совпали на `original/`.

Тесты сцены (`crates/k1-game/tests/original_scene.rs`, `crates/kn-game/tests/original_facade.rs`): позиции объектов совпадают с формулой эталона, куски тайлов покрывают все непустые клетки и несъеденные декорации, оверлеи следуют данным карты (проходимость, свет), список отрисовки детерминирован, все текстуры сцены декодируются, `check` не даёт ошибок и его статистика воспроизводима.

Округление половинок в `character_cell`/`rect_cells` — к чётному (`round_ties_even`), как `round()` в Python: обычный Rust-`round` расходился бы на `.5`.

Проверка записи из AGENTS.md для Rust та же: все файлы обоих изданий после «прочитать → записать» совпадают с оригиналом побайтно.
