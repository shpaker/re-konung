# NEWH.RES — изображения меню новой игры

`NEWH<width><language>.RES` (`NEWH640R.RES`, `NEWH800E.RES`, …) содержит
13 изображений: фон, подложку, точку выбора, пары портретов трёх героев
и кнопки страницы. В каталоге игры лежит по файлу на разрешение (640, 800)
и язык издания (R, E); игрок открывает его тем же способом, что оригинал.

**Подтверждено:** все четыре файла обоих изданий разбираются до последнего
байта, каждая запись потребляется до объявленного размера
(`k1-data/tests/original_newh_res.rs`). Python-копии нет: формат нужен только
окну игры. Найдено самостоятельно по структуре Slavik
`game_newgame.cpp:96-124` (`LoadNEWH`) и `resources.cpp:582-630`
(`LoadRL16BitImage`); код не копировался, декодер следует байтовому потоку.

<a id="the-file"></a>

## Файл

Последовательность 13 записей без общего заголовка; последняя заканчивается
на последнем байте файла.

| Смещение | Тип | Смысл | Уверенность |
|---|---|---|---|
| +0 | 4 байта | Неизвестно, не читается; в наших файлах нули | Неизвестно |
| +4 | u32 | Размер записи изображения в байтах | Подтверждено |
| +8 | запись | RL16, ровно `size` байт | Подтверждено |

<a id="the-rl16-image-record"></a>

## Запись изображения RL16

| Смещение | Тип | Смысл | Уверенность |
|---|---|---|---|
| 0 | s16 | Ширина в пикселях | Подтверждено |
| 2 | s16 | Высота | Подтверждено |
| 4 | h × s16 | Байтовые длины строк; декодер пропускает их | Структура подтверждена; неиспользование по Slavik |
| 4+2h | поток | Последовательные строки | Подтверждено |

Читается байт `n`: `0` заканчивает строку, старший бит означает пропуск
`n & 0x7F` прозрачных пикселей, иначе копируются `n` little-endian u16
RGB555 (R — биты 10–14, G — 5–9, B — 0–4). Перевод 5-битного канала
в 8-битный: `(v × 255 + 15) / 31`, таблица `Lkp5To8` источника (Slavik `gfx.h:62-65`).

<a id="the-13-records"></a>

## Тринадцать записей

| Запись | Содержимое | Размер при 800 | Уверенность |
|---|---|---|---|
| 0 | Фон 800×600 или 640×480, заголовок запечён по языку | 481956 (R) / 462341 (E) | Подтверждено |
| 1 | Подложка 100×100 | 20404 | Подтверждено |
| 2 | Точка выбора 13×13 | 344 | Подтверждено |
| 3–4 | Портрет экранного места 0: выбран/обычный, 76×87 (56×65 при 640) | 12185 / 12179 | Подтверждено |
| 5–6 | Портрет места 1: выбран/обычный | 12287 / 12233 | Подтверждено |
| 7–8 | Портрет места 2: выбран/обычный | 12243 / 12221 | Подтверждено |
| 9–12 | Кнопки страницы 105×46, 102×46, четыре состояния | 7098…5734 | Подтверждено |

Порядок мест оригинала: 0 Драгомир (Game.N 1), 1 Михаил (Game.N 2),
2 Волк (Game.N 0), `game_newgame.cpp:276-365`. В нумерации Game.N
пары 7/8, 3/4, 5/6 (`k1_data::newh_res::PORTRAIT_RECORDS`). Шесть портретов
побайтно одинаковы между изданиями; различаются фоны с запечённым заголовком.
Инструменту, которому нужны только портреты, подходит любой язык.

Оригинал также рисует живую модель выбранного героя поверх фона
(`DrawNewGameChar`, `game_newgame.cpp:188-280`): тело и снаряжение берутся
из [GRAPH.RES](graph-res.md), не из этого файла.

## Rust

`k1_data::newh_res::parse(&bytes) -> NewhRes` — чистая функция,
изображения декодируются в RGBA с непримноженной alpha. Аналога Python нет:
формат нужен только Rust-окну игры.
