# Движок перемещения

Общий слой мелкой изометрической сетки, проходимости, занятости, маршрутов,
ходьбы и тика. Без Bevy и K1: особенности части в `k1-*`, показ в `kn-render`.

- `grid`: Cell, восемь Direction, клетка ↔ пиксели, несдвинутые lattice-координаты и расстояние.
- `passage`: Passage поставляет проходимость.
- `pace`: Pace поставляет длительность шага по направлению.
- `occupancy`: одна клетка — одно существо или резерв шага.
- `route`: find_route/Route, A* через `pathfinding::astar`.
- `walk`: Walker проходит готовый маршрут, выдаёт WalkState.
- `world`: World объединяет существ, тики, спор за клетки, поиск и Event;
  единственный выход событий — tick_step.
- `rng`: собственный детерминированный splitmix64.

route не знает тик/длительность, walk — проходимость и происхождение пути.
Они встречаются и считают время только в World. Passage — данные карты,
Occupancy — состояние движка, знающего текущие шаги/резервы.
Факты оригинала — [исследование перемещения](../../research/k1/movement.md); ниже наши решения.

<a id="decision-step-cost-and-the-a-heuristic"></a>

## Решение: цена шага и эвристика A*

Цена в восьмых долях пикселя: запад/восток 464, север/юг 256,
диагонали 265 = `ceil(8·√(29² + 16²))`. Эвристика — прямое расстояние
между точками клеток в тех же единицах, `u64::isqrt` с округлением вниз.

Метрика 10/14 не подходит ромбу 58×32: соседи на расстояниях 58,32,≈33,1 px.
Назначение диагонали 14, северу 10 переоценивает отношение 33,1/32,
и A* может вернуть не кратчайший путь. Цена фактической длины и неравенство
треугольника дают допустимую монотонную оценку
(`route_cost_stays_close_to_a_straight_line`). Диагональ округляется вверх:
цена не может быть меньше реального расстояния.

При нескольких конечных клетках кольца вокруг занятой цели из расстояния
до центра вычитается максимальный радиус кольца. Оценка допустима,
отдельный isqrt для каждого кандидата не нужен.
`Cell::lattice_distance`, расстояние Чебышёва в несдвинутой решётке,
используется для определения колец.

<a id="decision-routes-without-the-32-step-limit"></a>

## Решение: маршруты без предела 32 шага

A* ищет путь любой длины. Исходный предел не отражён в данных и не переносится
в современный движок (принципы продукта; [факт оригинала](../../research/k1/movement.md)).
Поиск через всю сетку стоит 0,2–0,4 мс, менее 1% тика 60 мс
([стоимость движка](#engine-cost)); этот предел не даёт нужной экономии.

<a id="decision-no-corner-cutting"></a>

## Решение: не срезать углы

Направления различаются способом касания клеток: восток/запад/север/юг
пересекают вершину ромба и разрешены только при проходимых обеих поперечных
клетках (`Direction::corner_flanks`). Экранные диагонали пересекают грань,
угла у них нет. В lattice-координатах это обычный запрет срезания диагонали
в восьмисвязной квадратной сетке.

Боковые клетки проверяются только по земле. Занятость целевой клетки
проверяет Occupancy; существо сбоку само по себе не должно перекрывать проход.

<a id="decision-one-channel-for-events"></a>

## Решение: один канал событий

Только tick_step выдаёт события. Межтиковый move_to помещает RouteSet/NoRoute
в общую очередь; на следующем тике они выходят первыми в порядке приказов.
Нет потерянных/двойных событий, потребителю нужен один источник.
Возвращаемое значение move_to — немедленный ответ: число шагов или Err(NoRoute).

World::add отвергает OutsideGrid, CellTaken, ImpassableCell:
нахождение внутри стены нарушало бы инвариант каждого тика.
World::remove события не создаёт: внешний слой сам запросил удаление
и знает причину. Ожидающие события поиска удаляемого существа также удаляются,
чтобы канал не ссылался на отсутствующее существо.

<a id="decision-who-yields-a-cell"></a>

## Решение: кто уступает клетку

С началом шага существо резервирует цель до его конца
(`Holder { standing: false }`):

- Встречный обмен невозможен: чужая стоянка или резерв блокирует начало.
- При одновременной претензии проходит меньший номер: обход по ID,
  резерв исключительный, результат детерминирован.
- Исходная клетка освобождается на том же тике окончания шага,
  следующий не ждёт лишний тик.
- Если цель стала непроходимой в процессе, шаг откатывается
  (`Event::TerrainBlocked`); существо остаётся в своей клетке и ждёт
  нового пути, не оказывается в стене.

Отдельное исходное правило уступания не восстановлено: Slavik просто
не входит в занятую клетку (game.cpp:2889-2895). Отдельной защиты взаимной
блокировки тоже нет: клетка освободится или сработает перестроение.
Случай без обхода описан в открытых вопросах.

<a id="decision-repathing-without-thrash"></a>

## Решение: перестроение без лишних поисков

Поиск — самая дорогая операция. Повторный поиск вызывается в одном месте,
если существо стоит с неисполняемым маршрутом (цель занята/непроходима),
выждало wait_before_repath_ticks (по умолчанию 12, ≈0,72 с), а с последнего
поиска прошло repath_cooldown_ticks (60, ≈3,6 с). Весь путь каждый тик
не проверяется: препятствие обнаруживается перед следующим шагом.
Новый приказ ищет сразу, повтор недавно неудавшегося подчиняется паузе ниже.

Оба параметра входят в WorldRules и настраиваются потребителем;
подтверждённых значений оригинала нет. Тест проверяет пересчёт после
блокировки и достижение цели после снятия препятствия.
Новый маршрут начинает шаг на том же тике
(`a_deferred_order_starts_its_first_step_on_the_border_tick`).
Раньше приказ во время ходьбы добавлял лишний тик простоя, 60 мс,
хотя между шагами одного маршрута паузы нет.

<a id="decision-a-repeated-order-is-idempotent"></a>

## Решение: повторный приказ идемпотентен

Цикл правил может посылать одну цель каждый тик. World::move_to хранит
Actor::last_commanded: повтор возвращает оставшиеся шаги, не сбрасывает
waiting_ticks и не ищет заново. Иначе маршрут не завершался бы.
Память сохраняется после прибытия; World::stop очищает её, новая цель заменяет.
Неудачная цель не считается принятой: её нужно повторить после освобождения
пути. Для неё отдельная память и ограничение частоты.

<a id="decision-a-failed-goal-is-retried-on-a-cooldown"></a>

## Решение: пауза перед повтором неудачной цели

Недостижимая область стоит 8,9–9,6 мс на поиск — шестая часть 60-мс тика
одного существа (#54). Actor::failed_goal помнит неудачную цель;
её повтор внутри repath_cooldown_ticks отклоняется без поиска и нового
Event::NoRoute. Ответ возвращает move_to, канал сообщает только реально
выполненный поиск. Проверки:
`repeated_unreachable_order_is_throttled_to_the_cooldown`,
`a_retry_inside_the_window_neither_searches_nor_reports_a_refusal`.

last_commanded при неудаче очищается, иначе освобождённая толпой цель
никогда не повторится (`deferred_no_route_can_be_retried_after_the_path_clears`).
Одна память запрещает лишний поиск принятого, другая откладывает нужный повтор.
Он поздний, но не отсутствующий
(`a_repeated_unreachable_order_gets_a_route_once_the_window_passes`).
Passage — запрос, не уведомление: движок не узнаёт момент изменения земли.
Механизм уведомлений нужен лишь при реальном потребителе (#54).
World::stop очищает failed_goal
(`stop_clears_a_failed_goal_so_the_next_order_searches`), другая цель
не задерживается (`a_failed_goal_does_not_hold_up_an_order_to_another_one`).

По [замеру поиска](#engine-cost) цель за колонной стены требует 4 поиска за 240 тиков
вместо 241, ≈37 мс против ≈2,2 с за 14 с игры. Это наше ограничение,
исходная частота повторов не восстановлена. Хранится одна цель;
чередование двух недостижимых ищет каждый раз
(`alternating_unreachable_orders_each_search_inside_the_window`).

Частота разных целей ИИ ограничивается выше: kn_game::rules::FailedOrderCooldown
после NoRoute держит приказы существа window_ticks и возвращает Applied::Held
без World. `an_unreachable_area_costs_one_search_per_window` проверяет
4 поиска за 40 тиков вместо 40;
`a_cooldown_bounds_the_searches_of_an_isolated_creature` — изоляцию.
Это слой правил: не задерживает приказ игрока после неудачи ИИ и не держит
поворот, не требующий поиска. Движок помнит цель, применение правил — тик.

<a id="decision-an-occupied-goal-takes-the-nearest-ring"></a>

## Решение: занятая цель заменяется ближайшим кольцом

Занятая/непроходимая цель ищет свободную замену по кольцам от центра,
радиус goal_fallback_radius по умолчанию 4. Берётся первое достижимое кольцо,
а не самая дешёвая клетка во всей области. **Свободная, но недостижимая цель**
не заменяется: find_route возвращает None, Event::NoRoute.
Иначе Arrived означал бы невыполненный приказ
(`a_free_but_unreachable_goal_does_not_take_a_ring_cell`).
Без обхода колец A* выбрал бы клетку ближе к существу, не к цели.
На кольцо отдельный поиск, для обычной свободной цели — один.
Радиус ограничивает худший случай в тупике; нет свободного места — отказ,
не паника. Уже стоящий у занятой цели получает пустой маршрут,
который считается выполненным.

<a id="decision-taking-a-creature-out-keeps-the-numbers"></a>

## Решение: удаление сохраняет номера

World::remove освобождает стоянку/резерв и удаляет состояние движения.
Приказ отсутствующему или повторное удаление возвращает UnknownCreature.

- ID никогда не используется повторно в жизни мира. Внешний слой может
  хранить его после удаления (например, труп, #75); старый ID не должен
  обозначить нового персонажа. Цена — растущий u32, около четырёх миллиардов
  размещений; один мир живёт одну карту.
- remove сам прекращает шаг и освобождает клетки. Отдельный обязательный
  stop позволил бы забыть резерв при смерти и навсегда заблокировать клетку.

Event удаления нет; ожидающий поиск этого существа удаляется
(`removal_drops_a_pending_search_event_of_the_removed_creature`), остальные
события сохраняют порядок. Сохраняется порядок обхода живых ID и повторяемость
seed/порядка удалений (`removals_replay_identically_under_the_same_seed`).
Это наш API, не подтверждённое правило исчезновения оригинала.

Слот остаётся, но тик обходит только отдельный упорядоченный список занятых ID.
Исторический замер release, Apple M4 Pro, `removal_cost.rs`, `#[ignore]`,
три запуска: 100 стоящих существ после 2000 пустых слотов — 0,24–0,28 мкс/тик,
0,35–0,37 мкс states(); обход всех слотов — 2,6–2,9 и 1,6–2,0 мкс.
Пара add+remove — 0,05–0,06 мкс в обоих вариантах. Учёт незаметен,
тик каждые 60 мс, размещения/удаления редки; выигрыш оправдан
(нагрузка смены состава — отладочный игрок #49).

<a id="decision-the-seed-breaks-ties"></a>

## Решение: seed разрешает равенство

Rng циклически сдвигает порядок проверки направлений. Равные по цене пути
зависят от seed и повторяются с ним; без равенства выбор одинаков при любом
seed. Генератор не задаёт игровые правила, выбор из данных остаётся выбором данных.

<a id="decision-what-the-engine-does-not-know"></a>

## Решение: чего движок не знает

Движок работает целыми тиками. Миллисекунды задаёт поставщик:
kn_game::TICK_MS, 60 мс для K1. Проходимость и длительность также внешние;
ноль трактуется как один тик, чтобы не было нулевого шага или паники.

Наружу выходят WalkState (клетка, пиксельная точка, предыдущая клетка,
цель, направление, наличие шага и оставшиеся тики) и Event (начало/конец,
прибытие, ожидание, препятствие, новый путь, отказ). Индекс направления
совпадает с таблицей оригинала; выбор кадра и рисование — дело представления.

<a id="open-questions"></a>

## Открытые вопросы

- **Толпа без обхода:** NoRoute сбрасывает приказ и останавливает существо.
  Само оно не возобновится; вызывающий повторяет приказ с ограничением
  repath_cooldown_ticks. Хранить ли цель до расхождения толпы — вопрос поведения;
  неподтверждённое ожидание/возобновление не добавляется.
- **Препятствие посередине пути:** обнаруживается перед шагом туда;
  обход начинается позже, зато нет проверки всех путей и лишних перестроений.
- **Перемотка:** движок идёт только вперёд. Просмотрщик для Step назад
  пересоздаёт Simulation и проигрывает до нужного тика; обратный тик
  не добавляется (#68, replay_simulation).
- **K2:** бег укладывается в длительность шага из данных;
  другие различия перемещения пока не исследованы.

<a id="engine-cost"></a>

## Стоимость движка

Release, Apple M4 Pro, сетка 160×320, `kn-game/tests/movement_cost.rs`
под `#[ignore]`; обычный cargo test не запускает замер:

```bash
cargo test --release --manifest-path crates/Cargo.toml -p kn-game \
    --test movement_cost -- --ignored --nocapture
```

| Операция | Время |
|---|---|
| Тик с 50 идущими | 1,7–1,8 мкс (0,034–0,037 на существо) |
| Тик с 500 идущими | 14,2–15,1 мкс (0,028–0,030 на существо) |
| Тик с блокировкой, амортизированный поиск | 1,9–2,2 мкс |
| Путь через всю открытую карту | 0,21–0,37 мс |
| Путь среди стен | 2,0–2,2 мс |
| Поиск рядом с 400 занятыми клетками | 2,8–3,0 мс |
| Недостижимая цель, вся доступная область | 8,9–9,6 мс |
| Запрос занятости | 0,017–0,018 мкс |
| Эвристика A* (isqrt) | 0,005 мкс |
| Сосед / клетка → пиксели | 0,002 / 0,001 мкс |

Разброс трёх последовательных запусков: короткие операции менее процента,
открытый маршрут почти вдвое; для него важнее порядок величины.
Для сравнения ([переключение слоя](rendering.md#layer-switch-cost)): группа 5131 спрайта — 0,15 мс,
разбор списка отрисовки — 26 мс. Тик 50 существ дешевле переключения ~90 раз,
разбора ~15 000 раз. Обычный путь 0,2–0,4 мс — 1–3 переключения,
1/65…1/125 разбора; худший поиск — треть разбора и 15% 60-мс тика.

Тик стоит микросекунды, основная цена — поиск. World ограничивает его
repath_cooldown_ticks; цикл недостижимых приказов оплачивает один поиск
на существо за окно, не каждый тик (#54).
