# Загрузка данных и сборка сцены

Границы крейтов задаёт [архитектура](../../../ARCHITECTURE.md).
Раскладки и уверенность — в [форматах K1](../../research/k1/README.md#format-status).
Python остаётся эталоном парсеров и рендеринга.

<a id="loading-and-parsing"></a>

## Загрузка и разбор

`k1-data::repo::GameDir` ищет файлы без учёта регистра, перечисляет карты
и состояния, читает байты. `FileSet` выбирает игру или обучение.
Парсеры/сериализаторы принимают байты/значения и не обращаются к файловой
системе. Запись карт, света и стартовых состояний побайтно точна;
графика только читается.

`game_edit` принимает индексы, не заимствованные записи: вызывающий код
не удерживает borrow при изменении состояния. Плотные резервы сохраняются,
ссылки переписываются. Политика правок и непроверенная совместимость
с самой игрой описаны в [Game.N](../../research/k1/formats/game-state.md#editing-the-roster).

Тесты форматов подменяют байты, не провайдеров. Trait для мока объявляет
потребитель при необходимости: accept traits, return structs. В k1-data
нет предположительных provider traits. Конкретные возвращаемые типы
GameDir и методы &self оставляют границу пригодной без преждевременной абстракции.

Повреждённые данные отбрасываются до опасного вычитания/выделения памяти:
RLE ограничивает размеры MAX_DIMENSION и пропуски шириной строки;
GRAPH.RES проверяет диапазоны палитр; OBJECTS.RES ограничивает огонь 20 слотами.
Проверка пропуска RLE повторена в Python и Tiled.

GRAPH.RES и OBJECTS.RES заимствуют буферы. Resources владеет байтами и разбирает
их внутри with_graphics; владеющие данными таблицы EXE, маски и огонь
разбираются один раз. `k1_game::scene::Graphics` держит заимствованные
таблицы на протяжении пакета сборок поз.

<a id="draw-list"></a>

## Список отрисовки

Сцена следует `konung/k1/render.py`: земля → верхний слой → рисуемые декорации →
тени → объекты/огонь и существа со стабильной сортировкой `(bottom, kind, slot)`
по низу картинки → свет, проходимость и маркеры Game.N.
Огонь остаётся над родительским объектом. Сырые декорации сохраняются
в данных, но не рисуются. Текста в сцене нет: подписи маркеров даёт UI
просмотрщика. Кольца маркеров приближают эллипсы PIL толщиной 3.

<a id="piece-groups"></a>

## Группы частей

Каждая часть содержит PieceGroup, доступный через kn-game: земля, декорации,
тени карты, объекты, существа, тени существ, маски света, проходимость, маркеры.
Группы управляют только видимостью: z задаёт позиция в списке, части разных
групп могут чередоваться. PieceGroup::ALL определяет порядок создания узлов.
`PieceGroup::is_shown_by` и фасадный `group_is_shown` отображают SceneOptions
на группы. Тени существ следуют оверлею Characters.

Полная сцена с отфильтрованными группами равна сцене, собранной только
для выбранных слоёв. `group_filter_matches_a_scene_without_the_layer`
проверяет все карты/издания, `pieces_carry_their_group` — фасад,
`every_group_of_a_real_map_gets_its_own_node` — узлы, z и наследуемую видимость.
У безоконного отчёта собственные настройки слоёв и статистика.

<a id="frames-and-animation"></a>

## Кадры и анимация

Piece.animation хранит текстуру слоя, смещение угла и длительность в тиках;
Piece.texture — базовый кадр. Тик K1 — 60 мс
(`k1_data::objects_res::TICK_MS`, Slavik game.h:30). В этом исследовании формата
тайминг непосредственно в оригинале не проверялся; это следует отличать
от последующего [исследования состояний существ](../../research/k1/creatures/animation.md).

- Огонь использует включительный диапазон EXE, один тик на кадр.
  Простые OBJECTS.RES — frame_count и frame_time; несколько кадров
  без frame_time не анимируются. Существо собирает все кадры состояния/направления.
- База — кадр записи. Порядок рисования вычисляется по нему один раз;
  выключенная анимация воспроизводит статическую картинку Python.
- Отсутствующее изображение слоя остаётся пустым кадром и скрывает спрайт;
  удаление сдвинуло бы время. LayerKey (Body, Shadow, Gear { slot }) соединяет
  слои несмотря на разный порядок последовательностей или пропуски.
- Одинаковые длительности/база и одни часы карты синхронизируют составные слои.
- Scene::texture_ids включает все кадры, поэтому недостающая текстура
  обнаруживается до воспроизведения. Записанная проверка ENG использовала
  около 450 уникальных текстур на карту против 300 статических и заняла ~5 с release.

Источник карты выбирает и состояние: Game.N для игры, TGame.N для обучения.
Общее состояние ошибочно ставило бы игровых персонажей в обучение:
зафиксированные количества ENG 17/5 вместо 8/2. Ошибка остаётся в отчёте
своей карты, не останавливая остальные. Пустой слот отличается от ошибки
декодирования, сохраняющей причину: повреждённый поток или палитра вне банка.

<a id="pose-cost"></a>

## Стоимость позы

Release, Apple M4 Pro, `konung.1` обоих изданий, 25 существ, разброс трёх
запусков `k1-game/tests/pose_cost.rs` с `#[ignore]`:

```bash
cargo test --release --manifest-path crates/Cargo.toml -p k1-game \
    --test pose_cost -- --ignored --nocapture
```

| Операция | Время |
|---|---|
| Разбор `GRAPH.RES` и `Objects.res` | 16–25 мс |
| Одна поза: слои и кадры состояния/направления | 57–61 мкс |
| Пересборка при смене состояния или направления | 66–72 мкс |
| Все существа карты в покое, 25 штук | 0,95–1,06 мс |

**Решение по результатам #36:** строить позу по необходимости и хранить
до изменения состояния/направления. Сборка занимает сотую долю 60-мс тика,
все существа — 38–42 мкс на каждого. Предзагрузка всех состояний/направлений
умножила бы работу в десятки раз без видимого результата. Кешировать стоит
разобранные ресурсы: один разбор равен 250–450 позам. Поэтому
`Resources::with_graphics` передаёт таблицы в замыкание, а
`k1_game::scene::Graphics` удерживает их при сборке поз.
